* Why cap-widening is dead for bash (the "X" — feeds d6444430)
1. *bash's steady-state merge-per-key cap is already 6* (the global
   maxStacksPerMergeKey default; bash has NO case in effectiveParseMergePerKeyCap),
   NOT the tight 1 cpp uses. cpp's fix relaxed a hard 1->16; bash is already
   wide at 6, and 6->32 changes nothing. The premise "cap hard-set to 1" is a
   cpp property, not a bash one.
2. *The 5 blob accept-with-error files are table-coverage defects, not
   merge-selection defects.* Reduced triggers:
   - =x="${y:+$y; }"= -> ERROR, but =x="${y:+z}"= -> clean. The parameter-
     expansion-body operator/suffix (`:+`, and by the RCA also `:-`, `//`,
     indirect `!`, substring) has no valid parse path once the replacement
     carries a `$`-expansion + `;`. This is the documented
     spec.bash-expansion-table-defect.rca class, here on the BLOB lane (the
     existing grammargen-lane witness is TestBashParameterExpansionOperatorReducer).
   - =echo ${sp:i++%${#sp}:1}= -> ERROR (substring `${var:off:len}` w/ arithmetic).
   - =add-zsh-hook -Uz chpwd (){ print x }= -> ERROR (zsh anonymous function;
     genuine grammar gap, .sh misclassification).
   No survivor budget can preserve a branch the LR automaton never generates, so
   widening merge-per-key / stacks is structurally inert.
3. *The round-9 hypothesis (alsa-info.sh = command/variable_assignments merge
   class) is DISPROVEN.* Every isolated command-vs-variable_assignments shape
   parses clean on the blob: =migrated="..."= then keyword, then function,
   =[[ $a > $b ]]=, =echo ... < /dev/null | grep=. alsa-info.sh's failure is a
   whole-file recovery cascade (root ERROR [0:27247]) whose sub-blocks —
   including the exact tail =if\nWGET=$(...); [[..]] && [[..]] && [[ `..` ]]\nthen..fi=
   — each parse clean in isolation. It is an accumulated GLR/recovery
   interaction, not a single mis-resolved conflict, and it is not cap-driven.
4. *The cpp retry-rung transplanted verbatim delivers zero.* bash sits in the
   identical retry-suppressed position cpp was (runtime profile sets
   SkipCompleteAcceptedErrorRetry). A temporary bash branch in
   fullParseRetryMergePerKeyOverride (return cppFullParseRetryMaxMergePerKey for
   a bash complete accept-with-error tree) FIRED its widened retry
   (RETRYDBG pass maxStacks=8 mergePerKey=16 stop=accepted hasErr=true) and
   still produced hasErr=true. preferRetryTree keeps the original: a pure no-op
   with a wasted second parse on 5 files. Reverted.

* Glossary
- merge-per-key cap :: max GLR survivor stacks retained per merge key; bash
  steady-state = 6 (global default), NOT cpp's 1.
- table-coverage defect :: the LR automaton has no valid parse path for a
  construct; no survivor budget can recover it (distinct from merge pruning).
- self-healing pin :: a test asserting the correct outcome that t.Skips while a
  known defect holds and auto-passes once fixed, no edit.
- accept-with-error :: parse reaches EOF and returns ParseStopAccepted but the
  root subtree contains an ERROR/MISSING node.
