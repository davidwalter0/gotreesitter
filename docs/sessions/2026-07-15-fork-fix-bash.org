Fix Bash-language parse failures in the pure-Go tree-sitter fork
=github.com/davidwalter0/gotreesitter=. Bash was the weakest priority

* Decisions Made
- The defect is in the pure-Go grammargen table generation (the "gen" lane),
  NOT the hand-ported bash external scanner. The committed ts2go blob
  (BashLanguage()) parses all the failing forms correctly, and both lanes share
  the SAME BashExternalScanner via adaptExternalScanner — so the scanner is not
  the differentiator; the generated lex tables are.
- ROOT CAUSE: bash has 29 external symbols, so it is routed through LALR state
  merging (lr.go:581 `>= 24 externals && !PreferPreciseExternalLexStates`),
  which collapses the per-context precision tree-sitter's own tables keep. The
  single merged post-`${` state (state 87 in the 46811-state automaton) carries
  a reduce-follow-WIDENED keyword (keywords are in the lex-mode widen allowlist)
  with no real parse action. dfa.go's `if hasKeyword { validSyms[wordSymbolID]
  = true }` then injects bash's keyword-capture `word` token into that state's
  lex mode even though `word` has no real action there. `word`'s charset
  includes `: = / , - !`, so on `${x:=y}` the broad `word` wins longest-match
  ("x:=y", 4 bytes) over the specific `_simple_variable_name` (=/\w+/ = "x",
  1 byte), swallows the operator, and forces the whole `${...}` into ERROR.
  tree-sitter C's precise per-state tables never expose `word` there.
- FIX (bash-gated, safe): new grammar flag SuppressKeywordWordShadow. In
  computeLexModes, drop the injected keyword-capture word from a state's lex
  mode when word has no real action, NO keyword has a real action (so injection
  came purely from widening), and a real-action pattern terminal would be
  shadowed. Gated per-grammar because computeLexModes is shared by all grammars
  (changing it globally would force go/swift/etc. blob regen+reverify).
- Note: `>&2`, `case ;&`, and the individual expansion forms all parse cleanly
  in the ts2go blob and in isolation; the corpus-block ERRORs cascade from the
  expansion mislex corrupting lexer/parser state for everything after.

* Glossary
- gen lane :: parser built by grammargen's pure-Go LR/lex table generator.
- ref/ts2go blob :: parser decoded from the checked-in bash.bin (built by the
  C tree-sitter generator); the parity reference.
- keyword-capture word :: the grammar's `word` token that keywords are lexed as
  and then promoted from (bash: `word: $ => $.word`).
- lex-mode widening :: grammargen adds reduce-follow / missing-recovery
  lookaheads to a state's lex mode to compensate for LALR merging.
