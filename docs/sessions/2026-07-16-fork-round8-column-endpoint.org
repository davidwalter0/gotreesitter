#+title: Session 2026-07-16 — gotreesitter/fork-round8-column-endpoint
#+date: 2026-07-16

* Session Topic
Fix the 4th UTF-8 Point.Column rune-counting path in the pure-Go tree-sitter
fork: the COMMENT node's endPoint, undercounted whenever a comment contains a
multi-byte UTF-8 character. Same bug family as the three already-fixed paths
(DFA lexer c3701e45, error-tree parseErrorTreeWithArena 0a346aa4, JSON
token-source json_lexer.go ee9e3a6d).

* Method / Tooling
- Read the three prior fix commits to establish the pattern (advance byte
  offset by rune's UTF-8 width, but only bump Column by 1 instead of by that
  width).
- Traced C's production comment path: grammars.CLanguage() blob parsing via
  plain Parser.Parse() uses the embedded DFA lexer (already correct); but
  grammars.ParseFile / the registry's TokenSourceFactory ("c" ->
  NewCTokenSourceOrEOF) is the actual production path real callers use, and it
  bypasses the DFA lexer entirely in favor of the hand-rolled CTokenSource.
- Found the bug in the shared grammars/token_source_common.go sourceCursor.advanceRune:
  advances offset by utf8.DecodeRune's byte width but bumped col by 1 (rune
  count). This cursor backs CTokenSource.commentToken/consumeBlockComment (c,
  cpp), JavaTokenSource.commentToken, HTMLTokenSource.commentToken,
  AuthzedTokenSource.lineComment/blockComment, and the generic/lua/toml
  lexers — one shared primitive, high leverage fix.
- Repro'd with a vendored tree-sitter-c oracle checkout at /tmp/tsc_oracle
  (tree-sitter CLI 0.26.11) via `tree-sitter parse`.
- Verified against the real corpus file used by the round7-c-fullstack
  session (afl.c, AFL++ source) using the local corpus at
  /home/david/.claude/jobs/f84fc485/tmp/blob-parity/corpus/c/, the existing
  Docker image gotreesitter/cgo-harness:go1.25-local, and cgo_harness's
  corpus_parity tool against the pinned tree-sitter-c oracle.

* Root Cause
grammars/token_source_common.go:55 sourceCursor.advanceRune — advanced
c.offset by the decoded rune's byte width (correct) but c.col by a flat 1
(rune count, not byte count). tree-sitter's Point.Column is a byte offset
from line start. Any comment containing a multi-byte UTF-8 char undercounts
its own endPoint by (byte width - 1) per such char, and — since the cursor's
column state feeds every subsequent token on the same line — shifts every
later node's start/end column on that line too. Row and byte offsets were
always correct.

* Fix
grammars/token_source_common.go: c.col += uint32(size) instead of c.col++,
matching the identical fix already applied to JSONTokenSource.advanceOneRune
(commit ee9e3a6d).

* Glossary
- Point.Column :: tree-sitter's column field — a BYTE offset from the start
  of the line, not a codepoint/rune count.
- sourceCursor :: grammars/token_source_common.go's shared byte/row/column
  tracking primitive used by several hand-rolled TokenSource lexers (c, cpp,
  java, html, authzed, lua, toml, generic).
- TokenSourceFactory :: per-language override registered in the grammars
  registry; when set, grammars.ParseFile/ParseFilePooled route through it
  instead of the embedded DFA-generated blob lexer. C/C++/Java/Authzed/JSON
  are registered by default; Lua/HTML/generic are not (see
  token_source_factory_builtin.go).
- blob path :: grammars.CLanguage() (or any LangEntry) production entry —
  what real callers of grammars.ParseFile get, as opposed to a raw
  gotreesitter.NewParser(lang).Parse() call that bypasses the registry.
