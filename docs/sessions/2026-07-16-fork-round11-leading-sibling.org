* Session Topic
Fix the cross-language "whole-file ERROR swallows the leading top-level
siblings" recovery-boundary defect on the BLOB (external-scanner TokenSource)
path for C and C++. Root-cause, one principled boundary fix, not per-file
signatures.

* Files Touched
- parser_recover_c.go — leading/trailing extra lift in cAcceptRootRebuild and
  cRecoverEOFAccept; ERROR-root named=true invariant.
- parser_reduce.go — panic-mode resync completed-sibling scan skips extras
  (they carry no LR GOTO); resyncPreservedNextState helper.
- grammars/leading_sibling_recovery_test.go — new regression test (teeth
  verified: fails pre-fix).

* Root Cause (verified)
When a C/C++ file fails to reduce to translation_unit, gt materializes a
whole-file / top-level ERROR through error recovery. THREE recovery sites folded
the file's leading trivia (the license comment) — and, per file, the leading
clean top-level constructs — INTO that ERROR instead of keeping them as
siblings before it:

1. =cAcceptRootRebuild= (parser_recover_c.go, the faithful ts_parser__accept
   port): the topmost non-extra subtree names the root and every earlier
   subtree (incl. leading extras) is prepended as its CHILD. For an ERROR root
   this over-extends its start backward across the leading comment. This is the
   WINNER for the 3 C exemplars (libintl / cache-view / deprecate).
2. =cRecoverEOFAccept= (parser_recover_c.go): collects all stack subtrees into
   one ERROR spanning rawFirst..rawLast — the leading comment is child[0].
3. =tryResyncErrorRecoveryMode= (parser_reduce.go, panic-mode top-level
   resync): its completed-sibling scan advanced by GOTO, but EXTRAS have no LR
   GOTO, so the FIRST leading comment (=lookupGoto==0=) terminated the scan at
   preservedEnd=0 → every following clean top-level construct collapsed into the
   ERROR. This is the path for the 3 C++ exemplars (display_list /
   dl_path_builder / Certifier).

The oracle (tree-sitter-c/-cpp) keeps the leading comment (and any clean leading
top-level nodes) as SEPARATE siblings and starts the ERROR at the first
genuinely-unparseable token — a recover-to-state outcome gt reaches via
recover_eof, so gt must localize the ERROR boundary to match.

* Decisions Made
- resync scan: treat extras as transparent (preserve as a sibling, keep the
  same state) instead of terminating the scan — extras genuinely do not
  participate in GOTO (tree-sitter shifts them at any state). resyncPreservedNextState
  mirrors this in both sibling-push loops (a bare lookupGoto would bail on the
  extra and fall back to the buggy leaf path).
- cAcceptRootRebuild / cRecoverEOFAccept: lift the leading AND trailing runs of
  EXTRA children out of the ERROR as separate top-level stack siblings; the
  result builder (buildResultFromNodes → synthetic root) wraps
  [leadingExtras..., ERROR(interior), trailingExtras...] in translation_unit,
  matching the oracle. Gated so a REAL (non-error) accept root keeps the
  faithful ts_parser__accept fold.
- SPAN CORRECTNESS (the KDL regression): cRecoverEOFAccept must keep the ERROR
  span at rawFirst..rawLast when NOTHING is lifted — a raw stack node's span can
  legitimately extend past its last VISIBLE child (open error region absorbing
  trailing whitespace). Using the last spliced child's end shrank the KDL root
  by 37 bytes. Fixed: adjust start only on a leading lift, end only on a
  trailing lift.
- ERROR-root named=true: isNamedSymbol has no metadata row for the sentinel
  errorSymbol (returns false); tree-sitter ERROR is named. cRecoverEOFAccept
  already hardcodes true — cAcceptRootRebuild now does too for errorSymbol
  roots.

* Glossary
- leading-sibling over-extension :: the ERROR node's START swallows the leading
  top-level nodes (esp. the license comment) that precede the error region.
- cAcceptRootRebuild :: parser_recover_c.go — faithful ts_parser__accept root
  rebuild at EOF; topmost non-extra subtree names the root.
- cRecoverEOFAccept :: parser_recover_c.go — recover_eof: wrap remaining stack
  subtrees in one ERROR and accept.
- resync completed-sibling scan :: parser_reduce.go — keeps already-reduced
  top-level items as siblings, wraps the failed suffix in one ERROR.
- extra :: comment/whitespace node; no LR GOTO, shifted transparently.
