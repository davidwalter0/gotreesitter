- **Root-caused the real corpus residuals instead**, via a fast/local

  comparison, robust to indentation differences) plus binary-search
  narrowing (careful to avoid the false positives that plain =head -n=
  truncation produces on an unbalanced/incomplete prefix):
  1. *Genuine, fixable bug found*: =parser_result_bash.go='s
     =normalizeBashProgramVariableAssignments= used a parent-type
     allowlist to decide whether to split a raw =variable_assignments=
     group back into individual =variable_assignment= siblings, and
     split unconditionally for every parent NOT in
     {command,redirected_statement,declaration_command,unset_command} --
     including =program=, =list=, =subshell=, =case_item=, etc. But
     =grammar.js='s =variable_assignments= is an ordinary member of
     =$._statement_not_subshell=, so it's grammatically valid (and kept
     GROUPED by the real oracle) as a direct statement child in ALL of
     those contexts whenever it's a genuine same-line multi-assignment
     (=VERBOSE= QUIET= OPTS==, =[[ cond ]] || A=1 B=2 C=3=). Confirmed
     via =usr/bin/socat-broker.sh= line 32 and
     =usr/share/alsa-base/alsa-info.sh= line 42 (both byte-exact
     verified against the oracle CLI). This is why the two named bug
     classes got blamed in the Round-5-final SCOREBOARD: the
     `[[ ]] || A=1 B=2` idiom and `declare -A` scripts are exactly where
     multi-assignment groups cluster, even though the mis-split wasn't
     about `[[ ]]`/`declare -A` parsing itself.
  2. *Fix*: replace the parent-type-only heuristic with a source-aware
     check (=bashVariableAssignmentsSpansNewline=) -- only split when a
     newline appears between two consecutive assignment children, which
     is only possible if gt's GLR/LALR statement-boundary handling
     merged what should have been >=2 separate =_terminated_statement=
     reductions (a genuine cross-statement merge artifact) rather than
     treating the newline as bash's own statement terminator. Threaded
     =source []byte= through the two normalizer functions to make the
     check possible.
  3. *Remaining residuals traced, NOT fixed (deliberately out of
     minimal-fix scope)*:
     - =usr/share/alsa-base/alsa-info.sh=: after the fix, gt correctly
       keeps =[[ $(ping...) ]] || KEEP_FILES="yes" UPLOAD="no"
       PBERROR="yes"= grouped as =variable_assignments= -- but the REAL
       oracle instead extends this into a =command= node that swallows
       the *following* =else= keyword as a bogus command_name (verified

       =(command ... name: (command_name (word)))= where the word's text
       is literally "else"). This is =grammar.js='s explicit
       =conflicts: [[$.command, $.variable_assignments]]= entry --  a
       genuine GLR shift/reduce ambiguity that real tree-sitter's
       dynamic-precedence/conflict resolution resolves one way and gt's
       GLR runtime resolves the other (arguably more sensible, but
       non-matching) way. This is the SAME class already documented and
       deferred for cpp/ts ("deep shared-GLR-core dynamic-precedence",

       confirmed cross-language to bash too. Not a scanner/table/simple
       post-parse fix; would need runtime GLR conflict-resolution work.

       input divergence in error-recovery SHAPE on already-invalid

     - =analyze_packages.sh=: divergence is a comment embedded mid
       multi-line pipe continuation (=grep ... | \\\n...\n\n# comment\n
       grep ... | sort | uniq= collapsing children across the comment
       differently than the oracle) -- unrelated to `declare -A` despite
       the file using it elsewhere.
     - =emacs-vterm-zsh.sh=: contains zsh-only =(){ ... }= hook syntax,

* Glossary
- blob path :: the production parser entry point
  (=grammars.BashLanguage()=, decoded via =ts2go= from a real
  =tree-sitter generate= run's =parser.c=), as opposed to the
  =grammargen= lane (gt's own from-=grammar.json= LR/lex table
  generator). This round's bugs and fixes are all on the blob path.
- merge artifact :: a raw-parse shape where gt's GLR/LALR
  statement-boundary handling accumulates content across a real
  statement terminator (semicolon/newline) into one production instead
  of reducing separately -- the failure mode
  =bashVariableAssignmentsSpansNewline= detects and repairs.
- dynamic-precedence conflict :: a grammar-declared GLR ambiguity
  (=conflicts: [...]= in grammar.js) where multiple locally-valid parses
  exist and the parser's runtime conflict-resolution heuristic (not the
  grammar tables) picks a winner; real tree-sitter and gt can pick
  differently.
